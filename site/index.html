Rename Windows clients automatically. No passwords.

HostRename renames domain-joined Windows clients and their AD computer objects from a rule you define, such as DE{Serial}. It works through a delegation in AD instead of a stored credential, and removes itself when it is done.

DownloadDocumentationSource on GitHub

Why HostRename

Built for administrators who have to rename hundreds of clients without handing out credentials.

🔑

No stored passwords

The rename runs as SYSTEM on the client. Permission comes from a delegation to SELF on the client OUs with 8 minimal rights. Principals are compared by SID, never by name.

🏷

Flexible name templates

Use {Name} and {Serial} with length control, prefix and suffix. If a serial number is unusable or duplicate, a stable future ID takes its place. 15-character NetBIOS rules and truncation rules are built in.

🛡

Idempotent and safe

Dry run with -WhatIf. The script can run any number of times and renames once. It checks for collisions in AD and verifies domain, secure channel and permissions first.

🔀

GPO or ACMP

Deploy with a Group Policy scheduled task that cleans up after itself, or with ACMP through one wrapper script and a clear exit-code contract: 0, 3010, 20, 21, 22, 1, 2, 4, 5.

📶

Network-aware

The network gate renames only over LAN cable or DirectAccess. It protects users on EAP-TLS WLAN and can ask for a LAN cable.

📜

Certificate renewal

After the rename, a new machine certificate can be requested so that strong certificate mapping (KB5014754) keeps working. Old certificates are removed only on request.

🔍

Traceable

Central CSV log with delivery retry, local log, and reporting values in the registry that you can use as ACMP custom fields.

🧹

Clean exit

Cleanup removes the scheduled task, the script and the local logs, and sets a marker key. An optional cleanup GPO removes the registry keys.

🌍

Language-independent

Works on German Windows because SIDs are used instead of account names.

⚙

Plain Windows PowerShell 5.1

No extra modules on the client. PowerShell 7 works in addition.

🔒

Hardened

The ACMP log folder is protected (owner and access limited to SYSTEM and Administrators). A 32-bit process on 64-bit Windows is refused before anything is written.

📖

Open source, MIT

Read it, audit it, adapt the naming rule. The rule lives in one script.

How it works

Each device is renamed exactly once. Afterwards HostRename removes itself.

  1. State checkAlready done, or a permanent error?
  2. Network gateLAN or DirectAccess only
  3. RenameLocal and AD object, in one step
  4. RebootExit code 3010
  5. CertificateOptional renewal for WLAN devices
  6. CleanupSets the done marker

This is the ACMP wrapper flow. The GPO path runs pre-check, rename and cleanup as a scheduled task (the gate and certificate steps are ACMP building blocks).

Deployment by GPO

  • A GPO copies the script from a central share and creates a scheduled task (SYSTEM).
  • The task starts after creation and 5 minutes after each boot.
  • It pre-checks, renames, writes the central log, then removes task, script and local logs.
  • The link starts disabled so you can separate pilot and rollout.

Deployment by ACMP

  • One Client Command runs Invoke-AcmpHostRename.ps1 as SYSTEM.
  • The wrapper calls state check, gate, rename, certificate and cleanup in one run.
  • It ends with one summary line and one exit code.
  • ACMP only needs to react to 3010 (reboot dialog) and 20 (LAN cable dialog).

GPO and ACMP are alternative methods. Never run both on the same device.

Quick start

Placeholders such as DE{Serial} are examples. Use your own rule.

  1. Configure and preview

    Set the variables in the block "ADJUST HERE" of Prepare-HostRename.ps1, then run a dry run in an elevated PowerShell.

    .\Prepare-HostRename.ps1 -Action Setup -WhatIf
  2. Set up delegation (and share and GPO for the GPO path)

    GPO path: share, delegation and GPO (the GPO link starts disabled). ACMP: the delegation on the client OUs is enough (plus the share only if you want the central log). See the documentation.

    .\Prepare-HostRename.ps1 -Action Setup                         # GPO path
.\Prepare-HostRename.ps1 -Action Setup -Component Delegation   # ACMP
  3. ACMP: preview on one device

    Run the wrapper with -WhatIf first (gate and rename preview only). Add -CorporateSsid if you have a corporate WLAN.

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Invoke-AcmpHostRename.ps1 -NameTemplate "DE{Serial}" -NoCentralLog -WhatIf
  4. Run it

    Drop -WhatIf. Start with a pilot group, and read the exit code and the last summary line.

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Invoke-AcmpHostRename.ps1 -NameTemplate "DE{Serial}" -NoCentralLog
